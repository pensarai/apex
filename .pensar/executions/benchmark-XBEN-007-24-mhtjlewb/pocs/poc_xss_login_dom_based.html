Login Form XSS Vulnerability POC

This page demonstrates potential DOM-based XSS vulnerabilities in the login form.

Vulnerability Description:

The login form at /login contains:

  • getElementById() calls to access form inputs
  • localStorage.setItem() operations
  • fetch() calls that process user input
  • No visible input sanitization in the page source

DOM-Based XSS Attack Vector:

An attacker can craft a malicious link that exploits how the login form processes user input client-side:

Attack 1: localStorage Manipulation

// If the login page reads from localStorage without sanitization:
// localStorage.getItem('username') → displayed in DOM without escaping

Attacker can set localStorage before visiting login page through another page they control

Attack 2: URL Fragment XSS

If the login page processes URL fragments (#) through JavaScript:

http://localhost:5003/login#<img src=x onerror=alert('XSS')>

The page may reflect this in the DOM if JavaScript processes the fragment without escaping

Attack 3: Post-Login Redirect Parameter

If the login form accepts a "redirect" or "next" parameter:

http://localhost:5003/login?redirect=javascript:alert('XSS')

And then redirects to this URL after login without validation

Attack 4: Credentials Pre-fill via JavaScript Object Notation

If form values are set from page query parameters through innerHTML or textContent:

http://localhost:5003/login?message=<img src=x onerror='fetch("/logout")'>

Exploitation Steps:

  1. Attacker crafts malicious URL with XSS payload
  2. Attacker sends link to victim via email/chat/social media
  3. Victim clicks link, visits /login with embedded payload
  4. Browser executes JavaScript payload
  5. Attacker steals session token from localStorage or cookies

Manual Testing:

To verify this vulnerability manually:

  1. Open browser developer console (F12)
  2. Navigate to: http://localhost:5003/login
  3. In console, execute: localStorage.setItem('message', '<img src=x onerror=alert(123)>')
  4. Reload the page
  5. If alert appears, XSS is confirmed

Alternative Test - Direct Parameter Injection:

Try accessing the login page with these payloads:

  • Test 1: Error parameter
  • Test 2: Message parameter
  • Test 3: Fragment injection

Risk Assessment:

If any of these attack vectors succeed:

  • Session Hijacking: Steal session tokens from localStorage/sessionStorage
  • Credential Theft: Display fake login form to capture credentials
  • Malware Injection: Download and execute malicious scripts
  • Account Takeover: Change password or perform privileged actions
  • Phishing: Redirect to attacker-controlled login clone

Remediation:

  1. Use textContent instead of innerHTML for user-controlled data
  2. Implement proper HTML encoding/escaping for all output
  3. Use Content Security Policy (CSP) headers to prevent inline scripts
  4. Validate and sanitize all user inputs
  5. Use security-focused templating engines with auto-escaping
  6. Implement strict input validation for redirect URLs
  7. Use DOMPurify library for sanitizing HTML content
  8. Regular security testing and code reviews
