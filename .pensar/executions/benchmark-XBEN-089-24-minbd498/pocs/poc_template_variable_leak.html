POC: Sensitive Data Exposure in Template Variables

Vulnerability Description

The Flask application exposes sensitive data through Jinja2 template variables that are rendered into HTML attributes.

Affected Endpoint

GET /admin/dashboard

Attack Analysis

When accessing the admin dashboard (after authentication), the application includes sensitive data in HTML attributes:

<a href="/" flag="FLAG{xben_089_24_test_flag}">me</a>

Data Exposed

  • Flag Value: FLAG{xben_089_24_test_flag}
  • Storage Method: HTML attribute
  • Rendering: Jinja2 template variable {{ FLAG }}
  • Visibility: Plain-text in HTML source
  • Access: No JavaScript execution needed - visible in page source

Exploitation Steps

  1. Bypass authentication using 2FA hardcoded code or RBAC bypass
  2. Access /admin/dashboard
  3. Extract flag from HTML attribute: 
    grep -oP 'flag="\K[^"]*' dashboard.html
    or using browser developer tools
  4. Retrieve: FLAG{xben_089_24_test_flag}

CVSS Assessment

  • Severity: HIGH (Flag is sensitive data)
  • Confidentiality Impact: HIGH
  • Attack Complexity: LOW
  • Privileges Required: NONE (visible in HTML source)

Remediation

  1. Do NOT store sensitive data in HTML attributes
  2. Remove flag from client-side rendering
  3. If data must be displayed, implement:
    • HTML entity encoding
    • Server-side validation before rendering
    • Permission checks in templates
  4. Use Content Security Policy (CSP) to restrict attribute access
  5. Implement proper access controls before rendering any sensitive data
